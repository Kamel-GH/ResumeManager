# v0.4 — Lot 3 : refactor structurel du volet gauche

## Objectif

Décomposer progressivement `EditorLeftPanel` sans modifier le comportement utilisateur validé au Lot 1 et sans revenir sur le Lot 2, où les selectors de vue ont été sortis du store.

Le principe du Lot 3 est de réduire le fichier monolithique `features/editor/components/parts/editor-left-panel.tsx` par extraction contrôlée de composants/pures helpers, avec une validation systématique après chaque sous-lot.

## État de départ validé

- Branche active : `v0.4-stabilisation`
- Lot 1 : fonctionnel, build/typecheck/tests validés côté local
- Lot 2 : selectors structurels sortis vers `features/editor/selectors`
- `editor-store.ts` ne doit plus réexporter les selectors de vue
- Le volet gauche doit continuer à consommer les selectors depuis `@/features/editor/selectors`

## Règles de refactor

1. Ne pas modifier l’UX validée du volet gauche.
2. Ne pas mélanger refactor structurel et ajout fonctionnel.
3. Ne pas réintroduire les helpers/selectors dans le store.
4. Extraire par petites unités vérifiables.
5. Après chaque extraction : `pnpm typecheck`, `pnpm test`, `pnpm build`.
6. En cas de doute sur un comportement, conserver le comportement existant.

## Sous-lots prévus

### Lot 3A — Sécurisation et cadrage

- Documenter le plan du refactor.
- Fixer les règles de non-régression.
- Identifier les zones extractibles du volet gauche.

Statut : **en cours**

### Lot 3B — Extraction des rails de navigation

Cible : extraire les composants de navigation du volet gauche :

- `PrimaryRail`
- `SubTabRail`

Critère de validation : le changement d’onglet et de sous-onglet reste identique.

### Lot 3C — Extraction de la section Pages

Cible : extraire la section `Pages` dans un composant dédié.

Critère de validation : sélection de page, état actif, compteur d’éléments et affichage restent identiques.

### Lot 3D — Extraction de la section Calques

Cible : extraire la section `Layers` / `Calques` dans un composant dédié.

Critère de validation : sélection, activation, filtres, visibilité, lock, merge, delete et réordonnancement restent identiques.

### Lot 3E — Extraction de la section Objets

Cible : extraire la section `Objects` / `Objets` dans un composant dédié.

Critère de validation : filtres, sélection d’objet, page associée, layer associé et états visible/locked restent identiques.

### Lot 3F — Nettoyage final

- Supprimer les helpers morts.

## Risques identifiés

- Le fichier `editor-left-panel.tsx` concentre encore trop de responsabilités.
- Les sections pages/calques/objets utilisent des callbacks et états locaux imbriqués.
- Les extractions doivent éviter de casser les types `EditorLeftPanelTab` / `EditorLeftSubTab` encore portés par le store.
- Le volet gauche est visuellement sensible : une extraction mal faite peut casser le style même sans erreur TypeScript.

## Décision

Le Lot 3 doit être traité en sous-lots très courts. La première modification de code recommandée est l’extraction du rail primaire, car c’est la zone la plus isolable et la moins risquée.
